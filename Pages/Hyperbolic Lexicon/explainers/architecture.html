A sentence goes in as bytes. Five exact stages turn it into token ids, a tree address for every word and an exact point in hyperbolic space, designed to come out the same in Python and in the browser. Three learned stages follow later, in floats. This page walks through all eight, with what the spikes measured, and ends with a lab that addresses a small hierarchy and places it exactly in the disk and the ball.

01

Where this sits

This page is the front end of the system map. Its focus node is stage D, the address: it takes the token ids and WordNet’s hierarchy, uses the norm-5 tree, and feeds the exact placement and the records.

Phase 0 is analysis, seven measurement spikes and a preregistration. No code for any stage existed then, apart from the shared cores this page loads unchanged; Phase 1 has since written stages A–E in the Python reference (Explainer 9), and Phase 2 in the browser core, lexicon_core.js (Explainer 10). The spikes S1–S7 have run; their scripts and captured outputs are in the spikes/ folder (Explainer 8), and this page links each output where it quotes it. They measured on data kept apart from every registered instance: WordNet verbs and adjectives, Owl Academy’s canon tree, synthetic words and repository Markdown. They fixed facts the design depends on, and they decide no claim. The eleven claims L1–L11 in PREREGISTRATION.md are registered REGISTERED; Phase 1 decided L2, L3’s Python side, L5 and L7, and Phase 2 L1, L3(f) and L4(a, b), all SUPPORTED; the rest are undecided.

How to read this page

exact: integers, rationals or bytes, identical in every engine. float: floating point, rounded at every step. A number called a spike result comes from a captured spike output, quoted as printed (“spike S3 measured …”). Lines that the spikes mark with “~” are timings or runtime versions on this container; they are labelled as such here. A value marked illustrative is made up to show the shape of a stage, because the thing it stands for does not exist yet.

Synset
A WordNet set of synonyms naming one concept, such as cat.n.01. Each has an 8-digit offset. The pin holds 82,115 noun synsets.
Hypernym
The more general concept: mammal is a hypernym of cat. WordNet writes it as an @ pointer, or @i for an instance.
Spanning tree
Keep one parent per synset, its first @ or @i pointer, and WordNet’s noun hierarchy becomes a tree with entity.n.01 at the root.
Word, letter
An address in the norm-5 tree. Letters 0–5 stand for the quaternions 1+2i, 1−2i, 1+2j, 1−2j, 1+2k, 1−2k. A word is reduced when no letter is followed by its conjugate, so the root has six children and every other node five.
Virtual letter
A letter that stands for no synset. A node with more than five children needs two or more letters per child; the letters after the first on such an edge are virtual.
Lorentz product
⟨x, y⟩L = −x₀y₀ + x₁y₁ + …. For two points on the hyperboloid, −⟨x, y⟩L = cosh d(x, y), so it ranks by distance without a square root or a logarithm.
MAP
Mean average precision. Rank every other node by distance from a query node, score how early its true neighbours come, and average over the queries; 1 is perfect. Graph-edge MAP counts the parent and the children as neighbours; closure MAP counts all ancestors and descendants.

Stages A–H

Eight stages take a sentence from bytes to a model’s output. The first five are exact and need no training. The last three learn, in floats, and two of them wait until every Stage-1 claim is decided.

B · TOKENIZEWordPiece on a pinned vocabulary: V0 “lex0” decides; BERT’s V1, pinned in Phase 1, is a second cell. (L1)

03

A · Normalise exact

Before text can be split into pieces it must be cleaned the same way everywhere. That sounds trivial. Spike S6 found that it is not: the three runtimes here do not carry the same version of Unicode.

The normaliser N_B follows the rules of BERT’s BasicTokenizer, in BERT’s order (D5 and the design):

  1. Read UTF-8 bytes; reject invalid UTF-8 and report its offset.
  2. Drop U+0000, U+FFFD and control, format and private-use characters (categories Cc, Cf and Co), except tab, line feed and carriage return, which become whitespace; unassigned code points (Cn) are kept, so that their word fails closed (below). Spaces (Zs) become a plain space. This is the rule in force since Amendment 1: google-research/bert drops only Cc and Cf, and Hugging Face’s copy every C category (Amendment 2’s erratum).
  3. Put spaces around CJK ideographs (BERT’s ranges), then split on whitespace.
  4. Lowercase each word as Python 3.13’s str.lower does at Unicode 15.1: full mappings, so U+0130 İ becomes two code points, and the Final_Sigma rule, so Σ becomes ς at the end of a word and σ elsewhere.
  5. Decompose (NFD: canonical decomposition, canonical ordering, algorithmic Hangul), then drop the combining marks (Mn). This strips accents: café becomes cafe.
  6. Split off punctuation (any P* category, and BERT’s ASCII ranges).

Pinned tables. Every Unicode fact N_B uses comes from a table exported once from Python’s unicodedata 15.1.0 and pinned by SHA-256 (reference/golden/unicode_15_1_v1.json, checked by make_unicode_v1.py --check). The JavaScript never calls String.prototype.normalize, toLowerCase or \p{…}. A word containing a code point that Unicode 15.1 does not assign fails closed: it becomes [UNK] and its byte offset is logged. The original bytes are never lost, because the shdccp/2 stream keeps them losslessly (Explainer 4).

Why the tables are pinned: spike S6

Spike S6 (output) swept every code point, 0 to 10FFFF without the surrogates (1,112,064 of them), through Node, Python and headless Chromium. On this container (a “~” line, the runtimes’ own versions): Node 22.23.4 reports Unicode 17.0 (ICU 78.3); Python 3.13.18 reports 15.1.0; Chrome for Testing 153 behaves as 17.0, inferred from its 159,801 assigned graphic and format code points. Node and Chromium agreed on every value. Node and Python differed on 9,990 code points, almost all of them unassigned in 15.1 and assigned since.

The table is small, and it is enough

Spike S6 built a prototype of the 15.1 table from Python’s unicodedata: 4,009 category ranges, 2,061 single-step canonical decompositions, 388 combining-class ranges, 1,433 lowercase mappings, and two Final_Sigma sets of 437 and 150 ranges; 142,041 bytes as compact JSON. Driven by that table alone, lowercase, Final_Sigma, NFD and mark-dropping reproduced Python’s own functions with 0 mismatches on all 1,112,064 code points, and 0 on 2,000 synthetic strings. One catch: Final_Sigma needs the Cased and Case_Ignorable sets, which unicodedata does not expose. S6 read them by probing str.lower, so the real export must include them. The prototype is not the pin; the pin is written in Phase 1.

L1 registers the test: on every WordNet gloss (117,659 strings), every UD English EWT sentence (16,622), the stress set and 2,000 synthetic strings, Python, Node and Chromium must give identical normalised bytes, tokens, ids, byte offsets and id-stream SHA-256. Its prediction names the risk points: Final_Sigma context, multi-code-point lowercase (U+0130) and canonical ordering. If L1 is refuted, a fallback N1 (bytes as given, BOM stripped, CRLF to LF, ASCII lowercase) is registered. Phase 2 found no difference in any of L1’s four cells, and every control failed: L1 is supported (Explainer 10).

B · Tokenize exact

WordPiece splits each normalised word into the longest pieces found in a fixed vocabulary. A rare word still gets ids; it just gets more of them.

WordPiece, BERT’s tokenizer, works greedily from the left: take the longest prefix that is in the vocabulary, then the longest piece of the rest, marked with ## to say it continues a word. A word longer than 100 characters, or one with no matching piece, becomes [UNK]. The rule is deterministic, so once the normaliser and the vocabulary file are pinned, every engine should give the same pieces. L1 tests that it does.

V0 “lex0” · now

8,192 entries, trained by the Python reference on the 117,659 WordNet gloss strings with the algorithm Amendment 1 fixed, then frozen and hashed before the decisive run (reference/golden/vocab_v0_lex0.txt, SHA-256 df227056…): 8,059 merges on an alphabet of 64 ASCII code points, so under V0 a word with a non-ASCII letter is [UNK]. The design puts [PAD], [UNK], [CLS], [SEP], [MASK] at ids 0–4, then the alphabet, then the merges in order. V0 decides L1.

C · Ids exact

Three different numbers attach to a token, and the design keeps them apart (D4): its token id, its tree address, and its engram/1 key. Only the first is the model’s input.

The id stream. A shard’s token ids are written as LEB128 varints: seven bits per byte, with the top bit set on every byte but the last. An id below 128 takes one byte and an id below 16,384 takes two, so every V0 id fits in two bytes and every V1 id in three. The stream is hashed with SHA-256, and that hash is part of what L1 compares across engines and what L8(d) requires Python and JavaScript to agree on. Byte offsets back into the original text are optional.

11110011 → F300001110 → 0E

The id 1,907 in LEB128: its low seven bits first, with the continuation bit set (F3), then the remaining bits (0E). The id is illustrative.

engram/1, demoted. The engram/1 key, the XOR of one fixed 64-bit grid per letter, is computed only as a checksum layer that Owl Academy can read, through the verbatim biochain_v1.js engramStreamFromText. It is off by default for corpora and never an input. It keeps only which letters occur an odd number of times, so anagrams share a key and numerals sit on the zero key (Explainer 1). Claim L2 registers how often that bites: on the WordNet lemma types (147,306 before N_B), at least 1% must share their key with another type; the prediction was 2–10%. Phase 1 found 52.6% (77,520 of the 147,305 types left after N_B): L2 is supported, and the prediction was wrong (Explainer 9). Spike S4 (output) also timed it: the verbatim engram layer took 6,933.7 ms on one full verb shard, against a median 40.9 ms for the whole synchronous grow of a shard (“~” timings on this container; Engram’s engram_core: 130.5 ms). That cost is a second reason it is off by default.

D · Address exact

Every WordNet noun synset gets a word of the norm-5 tree. Nothing is trained: a fixed rule reads WordNet’s own hierarchy and spells it out in letters.

The rule (claim L3)

  • The spanning parent of a synset is the first @ or @i pointer of its data line.
  • entity.n.01 sits at the word [0].
  • Children are ordered by synset offset.
  • Child k of a node with c children takes m = max(1, ⌈log₅ c⌉) letters: the m base-5 digits of k, most significant first, each choosing P.children(current word)[digit].

Each node has five onward letters, so up to five children get one letter each. A sixth child forces two letters on every child: 25 slots. A 26th forces three. The max(1, ·) gives an only child one letter instead of none. A child’s word extends its parent’s, so an ancestor’s word is always a prefix. L3(d) registers the full statement: u is a spanning-tree ancestor of v exactly when u’s word is a proper prefix of v’s. That turns the address prefix into a meaning: a prefix that two words share, if it is a synset’s word, names a shared ancestor, not the base-5 accident of engram/1 addresses (Explainer 1).

A worked example

Take a node with the word W = 00000000 (in the lab’s toy tree, mammal) and seven children. Seven is more than five, so m = ⌈log₅ 7⌉ = 2: each child writes k in two base-5 digits. After a word ending in 0, P.children allows [0, 2, 3, 4, 5] (1 would undo the 0); after a 2 it allows [0, 1, 2, 4, 5].

A 59- or 64-bit id for every word (D6)

A word is not yet a fixed-width number. The design numbers all reduced words in one sequence: first by length, then, within a length, by reading the letters as digits, the first in base 6 and each later one in base 5 (its index among the five children P.children allows):

id(w) = (number of reduced words shorter than w) + (rank of w among words of its length)
words of length n: 6·5n−1   words shorter than n: 1 + 6(5n−1 − 1)/4

The code is a bijection: every id is one word and every word one id. Words of up to 25 letters number 1 + 6(525 − 1)/4 ≈ 4.47·1017 < 259, so they fit in 59 bits (id59); up to 27 letters, about 1.12·1019 < 264 (id64). L3(g) requires the code to round-trip every noun word it covers. The design does not reuse engram_core.encode for ids: it always writes 28 letters, never uses the sixth root letter and records no length.

The 59-bit form is what the proposed SHD-CCP kernel 0xA, the Hyperbolic Address Tile, carries: the Form header in bits 60–63, even parity in bit 59, the id in bits 0–58 (the proposal; Explainer 2). Run read-only against SHD-CCP’s own Kernel Ontology tooling, it passes lint_kernel, layout_integrity (3 fields tile bits 0–63 exactly once) and glass_box_round_trip (1,000 random round trips), and Form 0xA is free in that registry. Inside Owl Academy’s and BioChain-AI’s shdccp/2 streams Form 10 is the ROT gate, so the kernel is never written there. On S3’s verbs, 5 words of 13,767 would need a continuation tile; the kernel leaves that for a later version, once L3 has measured the nouns.

A prediction this fixed

A rule fixed with the design sets the prediction for L6(c), which says the training-free exact H³ tree has graph-edge MAP at least that of learned Lorentz embeddings at d = 3: supported if S3’s verb MAP is at least 0.90, otherwise refuted. S3 measured 0.6309, exactly a 205-digit rational (SHA-256 2e428dd7…) that an independent Python recomputation reproduced. So the prediction registered for L6(c) reads refuted: the claim is expected to fail. That is a prediction, not a decision: L6 is decided in Phase 4 on the mammals.

One more reading of the same word comes later. Reduced mod a prime q, a word’s quaternion lands on a vertex of the Ramanujan graph X(5, q), the overlay SHD-CCP’s RFC 03 plans (claim L7; Explainer 2). It is a shard key, never integrity: LPS Cayley hashes have known collision attacks.

E · Placement in H³ and H² exact

An address becomes a point by walking it: each letter is one step of fixed length in a fixed direction, taken in the frame of the node before. With rational steps, every point has exact rational coordinates, and greedy decoding walks it back to the word.

The octahedral tree in H³: the primary store

Hyperbolic Oracles’ decoder3d.js (TreeEmbedding3D) already does this in H³. A node sees its parent along −x in its own frame and its five children along +x (letter index 0, straight on) and ±y, ±z (90° bends). Each step is a boost with t = 3/4, so cosh τ = 25/7, sinh τ = 24/7 and τ = ln 7 = 1.9459. A point at word length n is an integer vector over 7n. Hyperbolic Oracles proves that greedy decoding returns every node at every depth when t > 1/√2 (E2, proved).

A new exact tree in H²

The plane had no exact tree: hyperbolic_core.js’s H² TreeEmbedding uses Math.cos and Math.sin. The design builds one from directions whose coordinates are rational because they come from the Pythagorean triples 3–4–5 and 7–24–25 (D3):

  • Root letters 0–5 go along (1, 0), (3/5, 4/5), (3/5, −4/5), (−7/25, 24/25), (−7/25, −24/25) and (−1, 0): angles 0°, ±53.13°, ±106.26° and 180°.
  • Every later node’s children k = 0–4 take the first five in its own frame; the parent lies along (−1, 0).
  • A step is the rotation R(u) to the child’s direction, then a boost with t = (m − 1)/(m + 1). Then cosh τ + sinh τ = m exactly, so τ = ln m.

The H³ boost t = 3/4 decodes only 226 of 500 at depth 12 in the plane, because the plane’s directions are only 53.13° apart and a child’s subtree spreads past the half-way line toward its sibling’s direction; S2 measured that spread exactly. That failure is L3’s fourth control, which must fail. t = 11/13 (m = 12) decoded 500/500 at every depth from 2 to 28, with no exact ties in 390,000 greedy decisions and the sheet identity x₀² − x₁² − x₂² = 1 exact on all 30,000 points. So cosh τ = 145/24, sinh τ = 143/24 and τ = ln 12 = 2.4849 (D3).

S2 also looked past the design’s six values. m = 10 and 11 decode every sampled word too; the threshold lies between 9 and 10. An exact measure of how far a subtree spreads, seven levels down, leaves m = 12 a margin of at most 8.72° to the decision boundary (m = 10: 2.01°; m = 11: 6.00°). These are upper bounds: S2 measured the spread as a lower bound. On the depth-28 random words, m = 10, 11 and 12 cost 247/185, 235/167 and 225/152 bits, so m = 12 is also the cheapest of the three.

The plane costs 1.28–2.38 times H³’s bits per coordinate, or 1.28–1.56 times for the whole point over one common denominator. The reason is the denominators: each H² step divides by 24 (the boost) times 1, 5 or 25 (the rotation), where each H³ step divides by 7. (S1 and S2 sampled different random words, hence 139 and 142 bits for the same depth.) Floats give out early here too: the same H² construction in float64 decodes 500/500 only up to depth 8 and 0/500 at depth 20.

Why H³ is the primary store

H³ has six signed axes, exactly one per neighbour of a node, at 90° or 180° to each other; the plane must squeeze six directions into a circle. So the H³ tree uses the shorter step (ln 7 against ln 12), smaller denominators and fewer bits, its decoding is proved for every depth, and its code already exists and is tested. The H² tree’s decoding is measured, not proved: 500 words per depth to depth 28. That is why L3(e) checks every noun’s point in both trees. The plane’s tree is the 2D system’s view and a two-number feature; the float TreeEmbedding is kept for drawing only.

08

Exact ranking exact

To score the tree against WordNet, every query ranks every candidate by distance. In floats, deep rankings come out wrong. In exact arithmetic they are integers.

Because every Lorentz product of two points at word lengths na and nb is an integer over 7na+nb (spike S1), a ranking needs no fractions at all. Scale every point to one common power of 7, and the key −⟨Xu, Xv⟩L times that power is an integer: cosh d times a constant. Sorting integers is exact in BigInt and in Python’s int. In S3 the verb keys were at most 257-bit integers. Distances (acosh) are used only for display.

Here “breaks” means a float inversion: two candidates whose exact distances are strictly ordered come out in the wrong order. On the straight word floats mostly tie instead: from depth 10 its two growing coordinates, cosh nτ and sinh nτ, round to the same double, and products along its own line come out exactly 0 (from depth 12 with the float placement). Float32 products overflow from depth 23. Float decoding first fails at depth 13 on random words. The design concludes, and L4(b) registers, that float64 ranking is not certifiable at WordNet depth: the noun tree reaches spanning depth 19, so its deepest words have at least 20 letters, past these depths. L4(a) registers the converse: exact rank lists are identical in Python and JavaScript, and MAP and mean rank are equal as exact fractions, in both trees. Phase 2 supported both: float64 inverted an exactly ordered pair in 997 of the 1,000 noun queries, and Node gave Python’s rank lists, exact MAPs and mean ranks for the 1,176 mammal queries and noun queries 0–199 (Explainer 10).

Ties, counted against the query

Exact arithmetic finds real ties, and virtual letters make many: a neighbour and a non-neighbour at exactly the same distance. The rule (common rules of the preregistration) is pessimistic: inside a tie, every non-neighbour ranks before every neighbour, and tied candidates are listed by synset offset. There, a float evaluator that breaks ties by node index gave a different average precision from the pessimistic exact one on 562 queries; that is L4’s second control. Hyperbolic distance is also not tree distance: on the 937 words of at most 4 letters (S1’s radius-4 ball around the empty word), it reversed the order of two tree distances in 47,352 of 2,264,600 comparisons (2.09%), only where the tree distances differ by one or two hops.

Cost. S3 ranked 13,542 verb queries against 13,766 candidates in Node in about 2.62 ms per query, 191 ns per pair (“~”). At that rate 1,000 noun queries against all 82,115 nouns take about 16 s or more, since noun words are longer. L4 uses the 1,000-query noun sample Rng(1000).sample(82115, 1000) and the 1,176-node mammal subtree, where every node is a query.

11

F–H · The learned stages

The exact tree has two or three coordinates. A language model works in 128 to 768. So the hyperbolic geometry enters the model as a factor, a head and a view, not as the main embedding.

F · Static embeddings float

Phase 4 trains embeddings of the WordNet mammal hierarchy in Python float64 with a numpy reference trainer (D9): Riemannian SGD in the Lorentz model after Nickel and Kiela, and plain SGD for the Euclidean control, at d = 2, 3 and 50 (5 and 10 reported). The tables are then snapped to a 2−32 grid (fence.js dyadic and lift) and ranked exactly; L4(c) requires the snapped MAP to stay within 0.001 of float64 evaluation. L6 decides whether learned Lorentz beats learned Euclidean at low dimension and whether the advantage vanishes at d = 50 (Explainer 5). As an exploration, decodeExact can act as a codebook, sending a learned H³ point to its nearest tree word, to compare learned and constructed addresses.

G · The encoder float

Stage 2 is a Euclidean BERT-style encoder: 1–10M parameters on CPU in Phase 6, then BERT-mini and BERT-small on a GPU in Phase 7. It reads each token’s address as a hierarchy factor added to its input:

  • Prefix embeddings. The sum of learned embeddings of the address’s prefixes of length 1 to k, k ≤ 12: a tree positional encoding in the style of Shiv and Quirk (NeurIPS 2019), applied to lexicon addresses.
  • Log coordinates. A frozen factor: H.logOrigin of the exact point of the address cut to at most 12 letters, three numbers from H³ or two from H².

Why the cut at 12: a deep exact point cannot enter a float network without loss. Spike S1 saw float decoding fail from depth 13 and float ranking invert from depth 10. The prefix embeddings carry the full depth instead, as discrete symbols. Two existing pieces are deliberately left out: Engram’s register clock as a positional encoding (it is bookkeeping, not position) and its coupler as a binding of segments A and B (it gives integrity, not modelling). A fully Lorentz encoder (HyperCore) is a later, exploratory GPU arm.

H · The heads float exact

  • Masked language model. A tied softmax over the vocabulary. An ablation replaces it with distance logits −d(h, ptoken)/T against fixed truncated points.
  • Hierarchy head, after HiT (Explainer 5): a parent–child pair scores −(d + w·(‖parent‖ − ‖child‖)), with feature clipping (Guo et al., CVPR 2022). Its weight w, threshold and temperature are a few numbers, so PolyStepH can tune them in the browser (D11 allows heads of at most a few hundred parameters), or Adam on CPU.
  • Certified assignment. Outputs are snapped and sent to tree words by decodeExact or nearestExact: an exact answer to “which synset is this?”.
  • Browser demos of tiny exported models can use softmaxWeights and H.lorentzCentroid as distance attention, for inference only. The fence and guard stay descriptors of stored tables.
Registered later, and expected to be small

None of this is registered. The roadmap lists candidate claims for an amendment after the Stage-1 gate: the address factor against shuffled addresses and no factor on BLiMP, predicted a null result within ±1 point; hyperbolic against Euclidean hierarchy heads on HiT-style splits rebuilt from WordNet; a Poincaré probe against the Euclidean structural probe on UD English EWT; and PolyStep against MeZO and zeroth-order SGD on a fixed head at equal evaluations. Hyperbolic Oracles’ C1 found no hyperbolic advantage in optimisation (0 supported, 12 refuted, 1 inconclusive), and the literature’s gains on general NLP are modest or unchecked (Explainer 1).

Honest limits

What this front end does not do, what it costs, and what is still open.

  • Five of eleven are decided, and L4 in part. Phase 1 decided L2, L3’s Python side, L5 and L7 (Explainer 9), and Phase 2 L1, L3(f) and L4(a, b) (Explainer 10), all supported; L4(c), L6 and L8–L11 are registered, not tested. The spikes ran on verbs, a canon tree, synthetic words and Markdown; nouns may behave differently, and that is what the claims find out.
  • Branching is fixed at five. Nodes with more children get virtual letters, siblings crowd the parent, and graph-edge MAP falls: 0.6309 on the verb forest (spike S3). On nouns, L5 reports it against a combinatorial embedding’s 0.989 in 2 dimensions at about 500 bits (Sala et al. 2018) verified and predicts it falls short; Phase 1 measured 0.5679 in H³ and 0.5901 in H² on the noun queries (Explainer 9). Address variants that give heavy subtrees shorter words (Huffman-5), or that follow the tokenizer’s merge forest for ## pieces, come later, by amendment.
  • One parent only. The spanning tree keeps the first hypernym; 2,213 noun synsets in the pin have several. Closure MAP keeps them, the address does not.
  • Addresses belong to one WordNet. They depend on offset order and on family sizes. A new child renumbers the siblings after it, and a family passing 5, 25 or 125 children lengthens every sibling’s word (try it in the lab). The table is committed by a Merkle root, addrTableRoot; another WordNet version is another table.
  • One sense, no context. A token maps to its first-sense synset. Most ## pieces have no synset and get spelling-based addresses that carry no meaning.
  • Exactness costs bits. Depth-28 points take about 139-bit numerators in H³ and up to 2.38 times as many bits per coordinate in H². Exact ranking is quadratic in BigInt, so nouns are sampled (1,000 queries). Exactness moves the precision problem into integers; it does not remove it.
  • The plane is measured, not proved. S2 decoded 500 words per depth to 28, with a margin of at most 8.72° seven levels down; L3 checks every noun.
  • Pinned Unicode is a choice. It makes the engines agree by making them all behave like Python’s 15.1 tables, Final_Sigma included. Text using characters assigned after 15.1 becomes [UNK]. Every receipt records the runtime versions.
  • The vocabulary is ours. V0 is trained here on glosses; BERT’s V1, pinned in Phase 1, is only L1’s second cell. Results on V0 do not transfer to published BERT numbers.
  • The encoder may not help. Stage 2 starts only after the gate, needs BabyLM (from Hugging Face, reachable since the network was widened in Phase 1) and, at scale, a GPU, and is predicted small or null on general NLP.
  • engram/1 and X(5, q) stay out of integrity. One is letter parity; the other has known collision attacks. SHA-256 and the records carry integrity.
What this page decides

Nothing. It describes a design and quotes spikes. Decisions are made by the claims in PREREGISTRATION.md, on the instances and rules fixed there, and recorded in the ledger.
