Install and run

python3 -m venv .venv && . .venv/bin/activate

pip install -r requirements.txt                                      # polystep 1.1.1, numpy, pytest

python -m pytest -q tests          # 80 tests, about half a minute
python run_traces.py               # writes traces/*.json for the browser core
python run_bench.py smoke          # every benchmark and method once, tiny sizes
On this build machine

The PyTorch CPU index was unreachable, so the default PyPI build of torch (2.15) was installed; it runs on the CPU too. Its first import takes most of a minute, which is most of the test suite’s first-run time.

04

Using the step

from hpstep import Rng, PolyStepH, StepConfig, TriChannel
from hpstep.problems import ThreeColouring

prob = ThreeColouring(60, 4.4, Rng(1000))                 # B1: n = 60, average degree 4.4
cfg = StepConfig(epsilon=0.5, step_radius=0.6, block=8)   # move 8 vertices per step
solvers, states = [], []
for j in range(3):                                        # channels A, B, C
    s = PolyStepH(prob, prob.m, 2, cfg, Rng(10 + j))
    states.append(s.init_state(prob.init_points(Rng(20 + j), 4)))
    solvers.append(s)
tc = TriChannel(solvers, states, prob, clutch='membrane').run(budget=24_000)
print(tc.memory[-1])     # the last zero point's word: certified costs, their sum Y, the chain link

StepConfig covers:

  • the temperature and the radii, as floats or polystep schedules such as CosineEpsilon and PowerDecay;
  • the solver ('softmax' or 'sinkhorn');
  • the geometry ('hyperbolic' or 'flat');
  • the rotation ('cayley', 'cayley_exact' or polystep’s 'haar');
  • exact mode, the snap grid and the horizon;
  • probe_jitter, for polystep’s theory mode.

06

Three findings from building it

1 · polystep does prove convergence, under conditions

The Phase 0 pages said polystep makes no convergence claim. Its experiment code shows otherwise: its paper proves a convergence theorem in a “theory mode”. That mode uses a power-decay step radius \(r_t = r_0(t+1)^{-(1/2+\gamma)}\), square-summable and not summable, with a flat ε and probe jitter. The pages are corrected. Whether the theorem transfers to the hyperbolic step is a new open row in the ledger, T1, and the reference implements theory mode so that it can be tested.

2 · float64 cannot reach depth 8 of the tree from the root

B3’s deepest targets are about 24 units from the origin. There the hyperboloid coordinates are near \(e^{24} \approx 10^{10}\), and the constraint \(\langle y,y\rangle = -1\) falls below float64’s resolution: a depth-8 node computed from the root has \(\langle y,y\rangle \approx -48\). The limit sits near distance \(\tfrac12\ln(1/\varepsilon_{\text{mach}}) \approx 18\). The fix is the standard one for hyperbolic embeddings (a tiling-based model): each point is held in the frame of a tree node near it, and re-anchored after every step. The step does not care which frame it runs in (H4), so nothing about the method changes. A test now pins the failure, so it cannot quietly return.

3 · Direction-only decoders need a horizon

A colour depends only on a point’s angle, and a truth value only on a sign, so nothing stops particles drifting outward. In a trace run one did, past distance 18, where the exact snap’s \(2^{-24}\) grid can no longer hold it, and the next centroid overflowed. Every factor now stays in a ball of radius 8, the same in both geometries. A point that leaves is moved radially back: the nearest point of a convex ball, so a move never gets longer (H2 survives) and the decoded answer never changes. The membrane’s recentring has to respect it too; at first it did not.

Findings 2 and 3, and two smaller choices, are recorded in the preregistration as Amendment 1, dated before any tuning or measured run. None changes a preregistered size, budget, metric or decision rule.

The benchmark runner

python run_bench.py tune B1           # Phase 4: 24 tuning runs per method, seeds 9000-9023 -> settings.json
python run_bench.py run B1            # Phase 4: every cell, instance and seed -> results/B1.jsonl
python run_bench.py decide B1         # Phase 4: the paired bootstrap decision per claim and cell

The smoke run completes every benchmark with every method at tiny sizes and untuned settings. Its numbers say nothing about any claim. For C2, every hyperbolic step of B1 and B2 logs its Klein length and the block’s mean Klein radius, and each run reports their Spearman correlation.
