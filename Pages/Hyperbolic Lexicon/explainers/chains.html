01

Where this sits

A shard holds text; everything the front end derives from it travels as typed commitments; a manifest ties the shards of a corpus together; a signature says who committed. Explainer 4 designed this in Phase 0, before any measurement. Phase 3 built it and decided the four claims about it. This page’s focus node is the shards and manifests.

The code is the chain section of lexicon_core.js (lines 1,568–2,868 of its 2,928) and its Python twin in reference/lexicon/: chain.py (709 lines), records.py (303), manifest.py (201), attest.py (275) and verify.py (410). The runner is run_claims_phase3.cjs, with its Python half run_claims_phase3.py. Every number on this page comes from results/claims-phase3.json (summarised in claims-phase3.md), the console log phase3-console.txt, the registry snapshot phase3-registry.json, the dry run in results/dry/, PREREGISTRATION.md (L8–L11, D7, D8, Amendments 7 and 8), the commit messages, the source files themselves (their line counts and docstrings) and Explainer 4; the lab’s values come from your own browser. Where this page and those files differ, the files win.

How to read this page

supported means what the registered decision rule says, and nothing more. L8, L9 and L10 are exact: every case passed and every control showed its weakness. L11 is measured: the upper end of the 95% interval of the median is at most 250 ms, and its control, as Amendment 8 replaced it, holds. A prediction was written with each claim; it is not part of the rule.

Timings belong to this container. L11 is decided on time, on this container, as registered; every other time on this page is reported and marked “~”.

Shard
At most 60,000 bytes of UTF-8 grown into one unmodified shdccp/2 biochain (D8). C0 is WordNet 3.0’s noun glosses, one line per synset, offset TAB lemmas TAB gloss, cut at line boundaries: 148 shards, 147 of them at least 59,000 bytes.
Record
Owl Academy’s biochain object, fifteen fields in Owl’s order: chainId, stream, streamVersion, leafHashes, merkleRoot, weaveChiral, weaveMirror, segCuts, segments, engramStream, engramCount, engramMeanJ, origBytes, shippedBytes, value. With engrams off, the three engram fields are absent.
Engrams on, off
Owl’s growBiochain can add an engram layer: 16 hex digits of engram/1 for every word token. The Lexicon keeps engram/1 as a compatibility checksum, never an input (D4), and off by default for corpora (Explainer 3).
Commitment
A typed record kind of D7, a pipe-joined string hashed with SHA-256: LVOCAB/1, LADDR/1, LPREP/1 (one per shard), LCORPUS/1, LGROW/1.
Package
What a holder hands to the verifier: the record, its LPREP/1 string, an ATTEST/1 block, the LCORPUS/1 string with the shard’s inclusion proof, and an LGROW/1 string with its consistency proof (Amendment 7 item 6).
Session
What a verifying holder pins once: V0, the LVOCAB/1 string, the LADDR/1 string (its addrTableRoot recomputed from WordNet once per session) and the key-registry snapshot with its SHA-256.
Self-consistent, authentic
The verifier’s two verdicts. Self-consistent: the record, its derived layers and its place in the manifest agree. Authentic: a registered, unrevoked key signed exactly this LPREP/1. Explainer 4 defined both; Amendment 8 item 3 made the code follow it.
Tamper class
One of L10’s nine registered alterations, T1–T9, 50 records each (chapter 7).
Dry run
The runner on data no claim uses: Rng(4000 + i) synthetic shards, the verb and adjective gloss shards, tampers from Rng(5000 + …), the verb shards standing in for C0 (Amendment 7 item 8). It decides nothing.
Decisive run
The one run on the registered instances that decides: node "Pages/Hyperbolic Lexicon/reference/run_claims_phase3.cjs", on the code committed at 6da04be.

ATTEST/1 and the key registry

BioChain-AI’s format, unchanged: the payload ATTEST/1|keyId|keyVector|contentHash|epochToken, with contentHash the SHA-256 of the LPREP/1 string and keyId K- plus 24 hex digits of SHA-256 over the public key’s x|y. The signature is ECDSA P-256 over SHA-256 of the payload, as WebCrypto writes it: IEEE P1363 r‖s, 128 hex digits. Python’s cryptography verifies DER, so the signature is converted first (spike S7). The registry snapshot lists keyId, public JWK, keyVector and status (active, revoked or retired) and is pinned by its SHA-256.

The hardened verifier: ten checks, two verdicts

The checks column has one letter per check in the registered order: P passed, F failed, – not run (the first seven stop at the first failure). “Owl’s rule” is EngramCore.verifyBiochain on the tampered record. Owl’s own verifyIntegrity is asynchronous and lives in Owl Academy’s scripts/biomesh.js, which no page here loads; verifyBiochain repeats its steps (frame parity, leaves when present, the root when present, the chiral weave, the engram layer) with a synchronous SHA-256, and Engram’s tests check its verdicts against Owl’s own, word for word, on the five records in bridges_v1.json. The decisive run ran Owl’s own function, from the Owl checkout, on T1, T2, T8 and T9 (L10’s control 1). T5 and T6 are not here: they need a second shard’s attestation and a Tier-P twin, which a one-shard corpus does not have.

How the lab handles LADDR/1

Everything in the shard’s LPREP/1 is computed here except one field. The addrTableRoot inside LADDR/1 is an RFC 6962 root over map A’s 8,192 rows, and building map A needs WordNet’s noun and verb forests, read from the pinned 10,775,600-byte archive in the cache, outside the repository. A page cannot load it (and this lab uses no fetch at all, so it works from file:// as well as over HTTP). So the lab’s session is built from a given LADDR/1: the string both languages computed in the decisive run (chapter 3). The page checks that its SHA-256 is the recorded laddrHash, 83f09be9…, and then uses it as a pinned value, as a holder would. The decisive run recomputed it from WordNet once per session (1,277.8 ms in L11’s session); the lab does not recompute it, so its laddrHash is taken on trust. LVOCAB/1 is built here from the pinned V0 and table and the two pins the core carries (the NB spec’s SHA-256 and instance (a)’s digest), and its hash is checked against the run’s.

Try it
  • Grow, sign and verify with the gloss lines: 2,222 bytes, four chunks. All ten checks pass; both verdicts are true; Owl’s rule accepts too.
  • T1, T2, T8, T9: the hardened verifier fails them at leaves, crystal, weaves and canonical; Owl’s rule accepts all four. These are the gaps L10’s control 1 measured, and the signature still verifies: authentic stays true, because the LPREP/1 string was not touched.
  • T3 breaks both verdicts: the commitment no longer matches, and the signature was made over the old string. T4 breaks only authenticity: the record and its commitment are fine, the key is revoked.
  • T7 on the gloss lines fails at leaves, and Owl’s rule rejects it too (“leaf 0 mismatch”). Cut the text to between 721 and 1,439 bytes and frame 1 is the short last frame: the swap then fails at canonical, as two of the run’s fifty T7 records did.
  • Paste a full shard (up to 60,000 bytes) to see the verifier’s time in your browser beside L11’s 155.4 ms in Node; one byte more and the grower refuses, as Owl’s does.
What this lab is, and is not

It runs the functions that decided L8–L11 in Node, in your browser, on your text. It touches no registered instance and decides nothing. Its key lives only in this page’s memory and is gone when you leave; its signature says only that this page signed. Its corpus id (lexicon-lab-v1), spdx (NOASSERTION) and sourceUrlSha (the SHA-256 of page:explainers/chains.html) are labels for the lab, not registered values. It uses the decisive run’s epoch token, EPOCH-OFFLINE-2026-11-06, so the page’s port of BioChain-AI’s identity and key-vector functions can be checked against the values the run recorded. WebCrypto needs a secure context (HTTPS, localhost or a local file); where it is missing, the lab signs with the core’s own deterministic ECDSA, skips the attestation check, and says so.

What Amendment 8 changed, and why it says so

Disclosure: the engrams-off reading came after the dry runs

The registration does not say whether L10’s and L11’s packages are grown with engrams on or off. Amendment 8 item 1 fixed off, for three reasons it states: engram/1 was registered as a compatibility checksum, never an input (D4); the design published in Phase 0 has the engram layer “off by default for corpora” (Explainer 3); and L11’s prediction, about 50–150 ms, was built from spike S4’s codec-only timing, which has no engram layer. It also states what came first: the runner had read it the other way, as Owl’s growBiochain defaults to engrams on, and in those dry runs L11’s median on engrams-on packages was 243.5–265.5 ms, near the bar, against 157–182 ms with engrams off. The reading was fixed after seeing that. Those dry runs are not committed; the committed final dry run, already on 8c51e08’s engrams-off code, measured 156.2 ms off and 229.4 ms on.

So the decisive run timed both. On the same 147 shards’ engrams-on packages the median is 243.589 ms, interval [240.247, 246.673], reported and deciding nothing. Its upper end is also under 250 ms, by 3.3 ms; in the dry runs before the amendment it was not always.

Item 2: the control that could not show what it was for

The registered control reads: “a run with the attestation step skipped must be faster; otherwise the step is not being timed and the test is void.” The runner compared the two medians. Amendment 8 reports that in the dry runs the step cost 0.7–0.8 ms against a per-verification spread of 10–28 ms: with correct code the comparison failed by chance, voiding L11, and with the skip deliberately ignored, so that both arms did the same work, it passed. The review confirmed this as its one finding. Amendment 8 item 2 replaced the control, as Engram Mind’s Eye’s Amendment 1 had replaced one that could not fail, with the verifier’s own record of its checks: every timed full verification must record the attestation check as run and passed inside the timed window with a time above 0, and every attestation-skipped one must record it as skipped with every other check passed; otherwise L11 is void. The median comparison is still reported.

What this does not show

Four supported claims about one format, two codebases and one machine. They say a good deal about integrity, and little about anything else.

  • A signature proves who committed, not licence or correctness. An authentic verdict says that a key the registry lists as active signed this exact LPREP/1. It does not show that the spdx field is true, that the text is what its source says, that WordNet’s notice was kept, or that the content is right. A holder who grows an altered text and signs it with a valid key produces a package that is self-consistent and authentic; nothing here can tell.
  • The keys were throwaway. They were made in WebCrypto for the run, belong to no person or organisation, and only their public JWKs were written. Revocation was a status in a pinned snapshot, not a live lookup; key compromise, rotation and expiry were not tested.
  • The manifest is checked as the package presents it. The attestation covers the LPREP/1 string. The LCORPUS/1 and LGROW/1 strings in a package are not signed, so inclusion and consistency show that the shard sits in the tree the package names and that the tree grew from N − 1 shards; a holder must take the corpus root itself from a source it trusts. Each package proves growth from N − 1 only; L9 tested growth from every smaller size on the lists themselves.
  • Tier P was tested only as a format. The 26 Tier-P twins used the registered test salts, SHA-256 of lexicon-test-salt/1|j, which anyone can compute, so these commitments hide nothing; a real Tier-P shard needs a secret salt. The challenge audits Explainer 4 describes were not built. No restricted corpus was used: C0 is WordNet, Tier S. Tier P remains attestation plus audit, not public recomputation.
  • Nothing was published. No record went to Owl Academy’s or BioChain-AI’s Firestore; the registry was a file; their code ran unchanged from local checkouts at 7f45f35 and c975161, and nothing in either repository was changed. A later biomesh.js is a new test.
  • The nine tamper classes are the registered ones. Replays of old packages, rollback to an older corpus root, a forged registry snapshot (it is pinned by hash, not signed) and attacks on the code itself were not part of L10.
  • One machine, two engines. Node 22.23.4 and Python 3.13.18 (cryptography 50.0.1, OpenSSL 3.5.9) on this container, 4 CPUs. L10’s JS ran on Node’s WebCrypto, not a browser’s. L11 is a Node figure; another machine is a new measurement, and the lab’s browser times decide nothing.
  • L11 is decided on engrams-off packages. That reading was fixed after the dry runs, as Amendment 8 discloses. Engrams-on packages took 243.6 ms, reported. Owl’s own grower with its engram layer took a median 9.3 s a shard (~).
  • The exact weave is an order check, not a hash. Collision resistance still comes from the SHA-256 leaves under it. It travels beside shdccp/2 as weave3Sha in LPREP/1, proposed for shdccp/3 in place of the float weave; shdccp/2 itself is unchanged, float weave and all.
  • The lab runs the same functions on your text, with a given LADDR/1 and a key made in the page. It demonstrates the code and decides nothing.

The plan at the end of Phase 3: learned embeddings, and the two claims still open. As before: the definitions by amendment before any code, a tuning amendment before any measured run, dry runs, then one decisive run. Phase 4 has done it and decided both (Explainer 12).

On the mammal closure (1,182 synsets, 6,542 edges), with the numpy float64 trainer: (a) learned Lorentz beats learned Euclidean on closure MAP at d = 2 and 3; (b) not at d = 50; (c) the training-free exact H³ tree has graph-edge MAP at least that of learned Lorentz at d = 3, predicted refuted by spike S3’s rule; (d) learned Lorentz at d = 3 beats the exact tree on closure MAP. Learning rates tuned on seeds 9000–9023 and frozen by a dated amendment; measured runs on seeds 0–4. The protocol is the project’s own, after Nickel & Kiela’s paper and script, as Amendment 6 attributes it.
  2. L4(c) · Snapped tables rank like floats. Every L6 table at d = 2 and 3, snapped to the 2−32 grid with fence.js and ranked exactly, has MAP within 0.001 of its float64 evaluation.
  3. LBENCH/1. The benchmark receipt, the one record kind of D7 not yet defined (Amendment 7 item 3), is defined when Phase 4 first uses it.
What Phase 4 found

Amendment 10 fixed the definitions before any code. The numpy float64 trainer, the exact evaluator of snapped tables, the decisions and the runner in reference/, and the exact ranking of snapped tables in lexicon_core.js (SnapArm, evaluateSnapped), were then built on synthetic data, reviewed and dry-run on the solid.n.01 closure set; tests/parity-lexicon.cjs, now with the L6 trace, passes 22,586 of 22,586 lines. Registered tuning ran 240 runs, Amendment 11 froze the rates, and one decisive run followed at 515a4a1, 3,051 s on 4 workers. L6 is supported in all four parts. (a): learned Lorentz beats learned Euclidean on closure MAP at d = 2 (0.88–0.91 against 0.16–0.17) and d = 3 (0.95–0.97 against 0.22–0.23), every interval above 0. (b): at d = 50 Euclidean is ahead, 0.99997 against 0.968, every interval below 0, which the rule counts as support. (c): the exact H³ tree’s graph-edge MAP, 0.690653, is above learned Lorentz d = 3’s 0.458–0.477, against the registered prediction of refuted. (d): learned Lorentz d = 3’s closure MAP, 0.950–0.971, is above the exact tree’s 0.305408. L4(c) is supported: snapping to 2−32 moved no MAP by more than 9.37×10−6 over 40 tables. Every control showed its weakness. LBENCH/1 was defined by Amendment 10 item 12, and the run wrote 367 receipts. Amendment 12, an erratum, corrects one sentence of Amendment 11.
