Integration and Upkeep

The last phase connects the system to the rest of the site and makes it easy to keep working. You can reach it from the site catalog, from the Hyperbolic Oracles and Geometric Calculator menus, and from the Hyperbolic Oracles hub. It loads five shared cores without copying them. One command checks the system and every core it loads together, so a change anywhere upstream shows up here.

The system’s own pages carry its own menu set, engram-minds-eye, with three menus: the hub and the two pages, the ten explainers, and the systems it builds on. All three menu sets live in scripts/page-chrome-targets.json. node scripts/install-page-chrome.mjs writes the bar into every page, and --check confirms every page has it.

Not done here

Owl Academy does not link back. That would mean changing the Owl-Academy repository, which this project only reads: it pins Owl Academy’s code and checks against it, and never edits it. A link from Owl Academy’s Engram Mind Eye page to this hub is a change for that repository’s owners to make.

The browser core checks one of these assumptions as it loads: if hyperbolic_core.js’s clock schedule ever differs from Engram’s, engram_core.js refuses to start and says so. The rest are checked by the parity lines, which compare exact values with the Python reference. A change in a core’s results shows up as failing lines, never as a page that quietly does something different.

04

One command

tests/all.cjs runs every Node check of the system and of the cores it loads, then the site bar and the four pins.

node "Pages/Engram Minds Eye/tests/all.cjs" pass cores orbital_core.js 18/18 checks pass pass cores hyperbolic_core.js parity 169/169 trace lines match pass cores decoder3d.js parity 28/28 decoder lines match pass cores twin3d.js parity 21/21 twin lines match pass cores fence.js parity 101/101 fence lines match pass engram browser core against the reference 849/849 lines; 27/27 behaviour checks pass engram the 2D page engine 26/26 checks pass pass engram the 3D page engine 19/19 checks pass pass engram the bridges 34/34 checks pass pass engram links and the ways in 31/31 link checks pass pass site the site bar on every page pass pins engram/1 golden corpus engram_v1.json matches Owl Academy pass pins STRIX library and exports both match Owl Academy pass pins LATTICE-SEED/1 both match Owl Academy pass pins the bridges to Owl Academy both match Owl Academy 15/15 checks pass (about 75 s, most of it the twin trace)

The pins regenerate every pinned file from Owl Academy’s code and compare them with the committed files. They need an Owl-Academy checkout: by default the one next to this repository, or a path given as the argument. Without one they are reported as skipped, never as passed. The Python reference has its own 45 tests:

cd "Pages/Engram Minds Eye/reference" && python3 -m pytest -q tests

tests/links.cjs checks every relative href and src in the folder’s pages and explainers, and every #anchor against the ids of the page it points to. It also checks every link on the system map, every file in every site-bar menu set, and each way in from the table above. It finds the folder’s pages itself, so a new page is covered without editing the test. Its three controls must come out right on every run: a missing file and a missing anchor must be caught, and a real anchor must pass.

05

When something changes

Five kinds of change, and what each one needs.

ChangeDo
Code inside a segment of orbital_core.jsRebuild with build.py. rebuild-identical.sh lists the orbital pages that moved; commit them if the move was intended. Then run tests/all.cjs. If an engram result changes, port the change to reference/engram/orbital.py too, regenerate the traces (run_traces.py) and commit both together. The parity check will not let the two drift apart.
One of Hyperbolic Oracles’ four coresRun that core’s parity test, then tests/all.cjs. The names Engram depends on are listed in Hyperbolic Oracles’ README under “Used by”. Renaming one breaks this system.
Owl Academy changes its engram codeThe pins’ --check fails and names the file. Keep the _v1 files as they are: they define engram/1, LATTICE-SEED/1 and the version 1 session format that existing chains, seeds and exports rely on. Pin the new version beside them as _v2, with its own script. If a claim is to rest on it, register an amendment first, as with Amendments 1 and 2.
A menu or the site barEdit scripts/page-chrome-targets.json (four-space indent, final newline), run node scripts/install-page-chrome.mjs, then --check. The bar is part of the four built orbital pages, so rebuild-identical.sh will show them as moved: commit the reinstalled pages.
A new module or page hereThe five things on the hub: the code, an explainer, a node on the map, a ledger row for anything it claims, and tests. Add its test to tests/all.cjs. tests/links.cjs picks up the new page itself.

Eleven claims have been decided: nine supported, two inconclusive, none refuted. The two inconclusive claims are about the same thing. The guard names a corrupted stored distance correctly 96 times in 100, short of the 99 its rule asked for. E10 showed why. Each miss is a tie, or a corruption that leaves no quadruple above ln 2: the guard runs short of witnesses, not of blame. Naming the pair from fewer witnesses would need more than four-point counts, such as the stored distances’ own history. That would be a new claim, registered before any code for it.
