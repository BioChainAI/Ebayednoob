01

Where this sits

The ladder is the last layer of the system map. It scores what the exact placement, the learned static embeddings and, later, the encoder’s heads produce. Its own outside data is BabyLM, BLiMP and GLUE; WordNet and UD English EWT reach it through the earlier stages.

Each rung asks one question and is climbed only when the one below it holds: the same ids in every engine, then the geometry against a real hierarchy, then word meaning, grammar and sentence tasks. Stages 0 and 1 run fully in this container (4 CPU cores, 15 GB RAM, no GPU); the rest need blocked hosts or a GPU (Explainer 6 has the three compute tracks).

This page is a design, not a report. No number on it is a Lexicon result. The WordNet and UD English EWT numbers are Phase 0 pins: counts and hashes measured from the pinned archives (wordnet_v1.meta.json, ewt_v1.meta.json). Numbers called “a planning check” or “an estimate” come from the design and wait for a spike or a run. Spikes S1–S7 are still running, and nothing here quotes them (Explainer 8).

How to read the marks

Every published score carries the survey’s grade. verified: read from a repository or source code (for Sala et al., confirmed against the paper by the cross-check). likely: from a search summary of the primary paper, which could not be opened because arxiv.org and aclanthology.org are blocked here. secondary: only from someone else’s summary or table. Where the survey’s adversarial cross-check corrected a survey, the correction is used.

Where a stage can run: here in this container, browser or CPU; net needs a host that is blocked here (huggingface.co, osf.io, zenodo.org and others); gpu needs a GPU, on the user’s hardware or in the cloud.

03

Stage 0: determinism and the tokenizer

Before any geometry, the text has to become the same numbers everywhere. If Python and the browser disagree on a single byte, nothing computed on one side can be checked on the other. So Stage 0 has two hard gates and a handful of descriptors that are reported but never optimised.

Normaliser
The step that cleans text before it is split: lower-casing, splitting off punctuation, and removing accents by decomposing letters (NFD) and dropping the combining marks. The Lexicon’s N_B follows BERT-uncased’s rules on Unicode 15.1 tables exported from Python and pinned by SHA-256 (Explainer 3).
WordPiece
BERT’s subword tokenizer. Each word is cut, from the left, into the longest pieces found in a fixed vocabulary. Pieces after the first carry a ## mark: cats → cat ##s. A word with no possible cut becomes [UNK], the unknown token.
Fail closed
On a code point that Unicode 15.1 does not assign, N_B emits [UNK] for the word and logs its offset, rather than guessing.
Id stream
The token ids of a text in order. Its SHA-256 is one 64-hex-digit fingerprint: equal fingerprints mean byte-identical streams.

Gate 1 · byte identity (claim L1)

The Python reference (the authority), Node 22 and headless Chromium must produce identical normalised bytes, token strings, token ids, byte offsets and id-stream SHA-256 on every instance. The JavaScript never calls String.prototype.normalize, toLowerCase or \p{} classes, because the engines here ship different Unicode versions: Node 22.23.4 has Unicode 17.0 (ICU 78.3), Python 3.13.18 has unicodedata 15.1.0. Tables are data, so the platform’s version cannot leak in.

  • Instances. Every WordNet 3.0 gloss: 117,659 strings, one per synset (82,115 nouns, 13,767 verbs, 18,156 adjectives, 3,621 adverbs). Every sentence of UD English EWT at commit 4a4d77f: 12,544 train, 2,001 dev, 2,077 test. The Unicode stress set spike S6 writes. 2,000 synthetic strings from a registered pool of scripts, marks, controls and emoji.
  • Vocabularies. V0 “lex0”, 8,192 entries trained on the glosses and frozen by hash, decides. V1, bert-base-uncased (30,522 entries, Apache-2.0), is a second cell only if pinned in time; it needs huggingface.co net or a copy the user supplies.
  • Rule. Exact and all-or-nothing, per vocabulary and per runtime. One differing instance refutes and is recorded as a counterexample.
  • Controls that must fail. A normaliser that uses the platform’s own functions must differ somewhere on the stress set. Shortest-match-first WordPiece must differ on the glosses. Turning accent stripping off must differ on the glosses or EWT. If any of these passes, the test cannot see what it claims to see, and the cell is void.

Gate 2 · engram/1 collisions (claim L2)

engram/1 is the 64-bit key the existing systems give a word: the XOR of one fixed grid per letter. It keeps only whether each letter occurs an odd or even number of times (rank 26 over GF(2)), so LISTEN = SILENT, and numbers and words such as noon land on the zero key (Explainer 1). L2 measures how often that bites on a real vocabulary: the share of WordNet’s 147,306 distinct lemma types that share a key with another type. Supported at ≥ 1%; the prediction is 2–10%. The control, a 64-bit SHA-256-prefix key on the same types, must show no collision at all, and Python and Node must produce the same key table. Whatever the share, engram/1 stays a compatibility checksum, never a token id (decision D4); L2 measures what using it as an id would cost.

Gates, not goals

Three large studies found that these numbers predict downstream quality weakly. Ali et al. (NAACL Findings 2024), with 24 models at 2.6B parameters: fertility and parity do not reliably predict downstream performance. Schmidt et al. (EMNLP 2024), with 64 models from 350M to 2.4B: fewer tokens does not mean a better model, and pre-tokenization matters. Lotz et al. (ACL 2025): compression alone is unreliable. All three likely.

So the descriptors catch a broken tokenizer (a flood of [UNK], a fertility that explodes on one script) and are never used to claim one tokenizer is better. No published fertility for BERT’s WordPiece on English was found, so every comparison is computed here, on the same text, with both vocabularies.

Stage 1: the WordNet hierarchy

This is where hyperbolic geometry has its strongest published record, and where this stack can decide something now: does the exact, training-free LPS tree carry a real linguistic hierarchy? Everything runs here, exactly, on WordNet 3.0.

The data, pinned

WordNet 3.0 comes from nltk_data on GitHub (wordnet.zip, 10,775,600 bytes, SHA-256 cbda5ea6…), fetched once into a cache outside git and re-checked by make_wordnet_v1.cjs --check. A synset is one sense shared by a set of words; a hypernym is its more general sense (a dog is a kind of canine). Following hypernym and instance-hypernym links upward from every noun gives the closure: every (noun, ancestor) pair.

Two protocols, never equated

The same embedding can score very differently under the two, so the Lexicon reports both and never compares a number from one with a number from the other. The design pairs Sala et al.’s numbers with graph-edge reconstruction and Nickel & Kiela’s with closure reconstruction.

The metrics

MAP
Mean average precision. For one query, rank every other node by distance. At each true neighbour, take the precision so far: true neighbours ranked at or above it, divided by its rank. Average those over the query’s true neighbours (AP), then average AP over all queries. 1 is perfect.
Mean rank
For each true neighbour, one plus the number of non-neighbours ranked ahead of it, averaged over all true neighbours of all queries. 1 is perfect.
Pessimistic ties
Exact distances can tie. Decisions place tied non-neighbours ahead of the true neighbour, the worst case, so a tie can never help a claim. Fractional ties, the average over every order of the tied block, are reported beside them.
Computed exactly
Ranks come from the exact Lorentz inner product of exact points, compared as integers, so MAP and mean rank are exact fractions, identical in Python and JavaScript (L4). Float64 ranks can invert on deep words; a planning check saw straight paths invert at depth 11–12.
Distortion
How far distances in the space stray from distances in the tree: the mean of |dH / (τ · dT) − 1|, where dT counts tree edges, dH is the hyperbolic distance and τ is one step’s length (ln 7 in the H³ tree). 0 is perfect.
Bits per node
What an address costs to store: letters × log2 5 ≈ 2.32 bits per letter. A learned table snapped to a 2−32 grid costs d × 33 bits per node: 66 at d = 2, 99 at d = 3.
Cone F1 (later)
Ganea et al.’s protocol: train on the basic edges (the transitive reduction) plus 0, 10, 25 or 50% of the other closure edges, then test whether held-out pairs are recognised. F1 is the balance of precision and recall.
HiT F1 (later)
Hierarchy Transformers’ tests. Multi-hop: train on one-hop edges, test transitive ones. Mixed-hop: an incomplete hierarchy, possibly with unseen entities. Random and hard negatives; a threshold tuned on validation.

Exactness pays for precision; it does not escape it

Sala’s construction is the published family closest to the norm-5 tree, and it needs about 500 bits to reach 0.989 in two dimensions. One survey said our exact tree “avoids” that problem; the cross-check corrected it. Exact H³ points at depth 28 already carry 138-bit numerators and 79-bit denominators. Exact BigInt arithmetic pays the precision cost; it does not remove it. What exactness buys is certification: ranks, ties and MAP that are identical in every engine. Fixed branching also costs MAP: where a node has more than five children, “virtual” siblings sit as close as the parent, or closer. So the design predicts the noun graph-edge MAP will fall below Sala’s 0.989, and the closure MAP well below 0.87. Those are predictions, not results.

From a curated tree to human judgements about words: is “dog” a kind of “animal”, and how much? Hypernymy is asymmetric and graded, the kind of relation hyperbolic embeddings are usually proposed for. Controls where flat should win. SimLex-999, WordSim-353 and MEN measure similarity and relatedness: “cup” and “coffee” are related, but neither is a kind of the other. The design expects a Euclidean space to win there. A hyperbolic gain on hypernymy means more when it sits next to a flat gain on relatedness, because it shows the geometry is doing a specific job. For context, Poincaré GloVe (ICLR 2019) beat Euclidean GloVe on similarity and set an unsupervised state of the art on WBLESS likely.

Where it runs. The computation is small and runs on the CPU, but most of these files sit on hosts that are blocked here net. What can be built here is built from WordNet: HiT-protocol multi-hop and mixed-hop splits, rebuilt in Phase 4.

Stage 3: small MLM pretraining

The first stage with an encoder. A masked language model (MLM) learns by hiding some tokens and predicting them from the rest, as BERT does. The question is narrow: does feeding it the tree address as a hierarchy factor help it learn grammar from a child-sized corpus, at the same parameters and tokens?

The corpus: BabyLM

  • Tracks. Strict-small allows at most 10M words; strict at most 100M. From 2025 the total words seen are also capped, about 10 epochs: 100M for strict-small, 1B for strict likely. 2026 adds a multilingual track; which track to target is an open question.
  • Composition (2024 strict): CHILDES 29M, BNC 8M, Gutenberg 26M, OpenSubtitles 20M, Simple Wikipedia 15M, Switchboard 1M words; strict-small is about a tenth of each secondary.
  • Access. The corpus is on osf.io and Hugging Face, both blocked here net. Dry runs use WordNet glosses and UD EWT here; decisive runs need a wider network or the user’s machine. As 60 KB shards, strict-small would be about 1,000 independent chains and strict about 10,000 (Explainer 4).
  • Cost. About 6 · N · T operations to train: N = 5M parameters on T ≈ 1.3 × 108 tokens is about 3.9 × 1015, roughly 11–22 hours on 4 cores. That is an estimate; a calibration spike measures throughput first.

Scoring

BLiMP
67 paradigms × 1,000 minimal pairs: two sentences that differ in one place, one grammatical and one not. Accuracy is the share of pairs where the model prefers the grammatical sentence. Human agreement 96.4%; CC BY; on GitHub, reachable here; errata exist for its TACL Tables 3–4 verified.
Pseudo-log-likelihood
A masked model has no left-to-right probability, so a sentence is scored by masking each token in turn and adding up the log-probability of the true token (PLL).
PLL-word-l2r
Kauf & Ivanova (ACL 2023): plain PLL inflates scores for words split into several tokens, because the other pieces give the answer away. PLL-word-l2r also masks the rest of the word to the right. The choice changes BLiMP results likely, so it is pinned with a commit of babylm/evaluation-pipeline-2025 (Apache-2.0).
Structural probe
A linear map under which squared distances between a model’s word vectors track distances in the parse tree and squared norms track depth (Hewitt & Manning, 2019). The Poincaré probe (ICLR 2021) recovers syntax trees from BERT better than Euclidean probes. Scored by UUAS (the share of gold tree edges recovered, ignoring labels and direction) and the Spearman correlation of predicted with true depth, on UD EWT here.

08

Rules for every stage

The same rules hold on every rung and on every compute track, so that a number from the browser, the CPU and a GPU can be compared, and so that a null result is reported as plainly as a win. Decision D10 fixes what the tracks share: the tokenizer record, the manifests, the random generator, the metric code, the budgets and the receipts.

  1. A Euclidean control, always. Every hyperbolic claim is paired with a flat arm at matched dimension, matched bits and matched parameters, plus shuffled-address and content-hash controls. Bansal & Benton found Euclidean embeddings matching Poincaré at 50 or more dimensions likely, so a low-dimension win says nothing about high dimensions.
  2. Pinned scorers and pipelines. PLL-word-l2r at a pinned evaluation-pipeline-2025 commit; a GLUE fine-tuning recipe fixed before decisive runs; tokenization-scorer at a pinned version, with α = 2.5 stated. The 60.6-against-80 gap above is the reason.
  3. One tokenizer, one data identity, one seed scheme. A single LVOCAB/1 record names the vocabulary, the normaliser and the Unicode tables; L1 proves Python = Node = Chromium. Every corpus and split is named by its LCORPUS/1 root. Splits and MLM masks come from the shared generator, so every track masks identically. Instances use seeds 1000+i, secondary draws 2000+i, dry runs +3000, tuning 9000–9023, spikes 90000+i, training seeds 0–4; bootstraps take 10,000 resamples with seed 7.
  4. One metric implementation. Python is the authority. JavaScript reproduces exact metrics line for line; float metrics carry registered tolerances and per-item output hashes.
  5. Matched budgets, recorded. Gradient-free runs are matched on evaluations. Gradient runs record parameters, tokens seen, FLOPs, hardware, library versions, thread count and wall-clock time.
  6. Receipts. Each result is an LBENCH/1 record: claim id, the hash of what was scored, the evaluation set’s hash (gated sets by hash only), scorer and version, seeds, a hash per item’s output, the metrics’ hash, hardware and versions, and a class: reproducible (a CPU twin re-evaluation is bit-identical) or attested (float, single run). The browser re-evaluates every snapped table exactly, and a fixed BLiMP subsample of 67 × 100 pairs is scored on CPU and GPU within a registered tolerance (Explainer 4).
  7. A contamination receipt. SHA-256 sets of every 13-gram in the evaluation items, intersected with the training id streams; only the counts are published.
  8. Equivalence tests where a null is predicted. When the prediction is “no difference”, the claim says how small a difference counts as none, and is supported only if the whole interval sits inside that band. Engram’s E9b did this for recall after a one-letter substitution: 0.0002 against 0.0007 from a shuffled store, a difference of −0.0005 with interval [−0.0017, 0.0004], inside ±0.05 (Engram, Explainer 4). L12 would do the same with a ±1-point band on BLiMP.
  9. Grades travel with numbers. A literature number stays likely until its primary source is read, which needs arxiv.org and aclanthology.org. No first-round claim compares against a likely or secondary number.
Honest about the limits

Hyperbolic geometry clearly helps on explicit hierarchies such as WordNet, and in low dimensions. On general NLP it helps modestly or not at all. This stack’s own record agrees. Hyperbolic Oracles’ C1, “on tree-structured problems the hyperbolic step beats the Euclidean step at equal evaluation budget”, was refuted in 12 of 13 cells, with none supported and one inconclusive; on B4, the inconclusive cell, hyper3 scored 0.325 against flat3’s 0.334 (B4, its preregistration). engram/1, the only word key the stack had, is letter-count parity: LISTEN = SILENT, numbers and even-count words on the zero key, and recall after a misspelling at chance. So encoder-level effects at Stages 3–4 are expected to be small or null, and where a null is predicted the claim is written as an equivalence test (L12). The bet is on Stages 0–1: representation, where low-dimensional trees favour curvature, and certification, where exact results are identical in every engine.

Two tiers in the chain

Text travels inside a shard only when its licence allows redistribution: WordNet with its notice, UD EWT, BLiMP, public-domain Gutenberg and the team’s own text. Everything else publishes only hashes, roots, counts, SPDX licence identifiers, metrics and receipts, with salted commitments so that known text cannot be confirmed by guessing. That is attestation plus audit, not public recomputation. Explainer 4 has the records.
